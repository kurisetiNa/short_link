# 短链接分组功能说明

## 1. 功能概述

短链接分组模块位于 `admin` 服务，用于让不同登录用户管理自己的短链接分组。当前已实现：

- 新增分组
- 查询当前用户的分组
- 修改分组名称
- 逻辑删除分组
- 调整分组排序

核心代码位置：

- 控制层：`admin/src/main/java/com/nageoffer/shortlink/admin/controller/GroupController.java`
- 服务接口：`admin/src/main/java/com/nageoffer/shortlink/admin/service/GroupService.java`
- 服务实现：`admin/src/main/java/com/nageoffer/shortlink/admin/service/impl/GroupServiceImpl.java`
- 分组实体：`admin/src/main/java/com/nageoffer/shortlink/admin/dao/entity/GroupDO.java`
- Mapper：`admin/src/main/java/com/nageoffer/shortlink/admin/dao/mapper/GroupMapper.java`
- 分组 ID 工具：`admin/src/main/java/com/nageoffer/shortlink/admin/toolkit/RandomGenerator.java`

## 2. 接口清单

服务默认访问地址示例：`http://127.0.0.1:8002`。

| 功能 | 方法 | 路径 | 业务参数 | 返回数据 |
| --- | --- | --- | --- | --- |
| 新增分组 | POST | `/api/shortlink/v1/group` | JSON Body：`name` | 无 |
| 查询分组 | GET | `/api/shortlink/v1/listGroup` | 无 | `List<ShortLinkGroupRespDTO>` |
| 修改分组 | PUT | `/api/shortlink/v1/updateGroup` | JSON Body：`gid`、`name` | 无 |
| 删除分组 | DELETE | `/api/shortlink/v1/deleteGroup` | Query：`gid` | 无 |
| 分组排序 | POST | `/api/shortlink/v1/groupSort` | JSON Body：分组排序数组 | 无 |

除业务参数外，这些请求还需要携带登录请求头：

```http
username: aaa
token: 登录后返回的token
```

业务参数决定“要操作什么”，请求头中的登录凭证决定“为哪个用户操作”。

## 3. 新增分组

```http
POST /api/shortlink/v1/group
Content-Type: application/json
username: aaa
token: {token}

{
  "name": "默认分组"
}
```

处理流程：

1. `UserTransmitFilter` 根据 Header 中的 `username + token` 从 Redis 恢复登录用户。
2. `GroupController` 将 JSON 转换为 `ShortLinkGroupSaveReqDTO`。
3. `GroupServiceImpl` 生成 6 位随机 `gid`。
4. 查询当前用户下是否已存在该 `gid`，冲突时重新生成。
5. 从 `UserContext` 取出当前用户名。
6. 构造 `GroupDO`，默认 `sortOrder = 0`。
7. `GroupMapper` 使用 MyBatis-Plus 将分组写入 `t_group`。

## 4. 查询当前用户的分组

```http
GET /api/shortlink/v1/listGroup
username: aaa
token: {token}
```

查询接口没有 Query 或 Body 业务参数，但会通过 Header 判断当前用户。核心查询条件为：

```java
.eq(GroupDO::getDelFlag, 0)
.eq(GroupDO::getUsername, UserContext.getUsername())
.orderByDesc(GroupDO::getSortOrder, GroupDO::getUpdateTime);
```

对应的 SQL 含义大致为：

```sql
SELECT *
FROM t_group
WHERE del_flag = 0
  AND username = '当前用户名'
ORDER BY sort_order DESC, update_time DESC;
```

因此，同时登录多个用户时，客户端在请求中选择哪一组 `username + token`，服务端就查询哪个用户的分组。

## 5. 修改、删除和排序

### 5.1 修改分组

```http
PUT /api/shortlink/v1/updateGroup
Content-Type: application/json
username: aaa
token: {token}

{
  "gid": "a3FgP9",
  "name": "新分组名"
}
```

修改时同时限定 `username`、`gid` 和 `del_flag = 0`，避免用户修改其他人的分组。

### 5.2 删除分组

```http
DELETE /api/shortlink/v1/deleteGroup?gid=a3FgP9
username: aaa
token: {token}
```

这里不是物理删除数据，而是将 `del_flag` 更新为 `1`。后续查询仅返回 `del_flag = 0` 的分组。

### 5.3 分组排序

```http
POST /api/shortlink/v1/groupSort
Content-Type: application/json
username: aaa
token: {token}

[
  {
    "gid": "a3FgP9",
    "sortOrder": 2
  },
  {
    "gid": "b8KdQ1",
    "sortOrder": 1
  }
]
```

服务会遍历数组，按 `username + gid` 更新每个分组的 `sort_order`。查询时优先按 `sort_order` 倒序，再按 `update_time` 倒序。

## 6. 分组数据

`GroupDO` 对应逻辑表 `t_group`，主要字段如下：

| 字段 | 含义 | 来源 |
| --- | --- | --- |
| `id` | 数据库自增主键 | 数据库 |
| `gid` | 6 位分组业务标识 | `RandomGenerator` |
| `name` | 分组名称 | 请求参数 |
| `username` | 分组所属用户 | `UserContext` |
| `sort_order` | 分组排序值 | 新增时默认为 0 |
| `create_time` | 创建时间 | MyBatis-Plus 自动填充 |
| `update_time` | 修改时间 | MyBatis-Plus 自动填充 |
| `del_flag` | 0 未删除，1 已删除 | MyBatis-Plus 自动填充/业务更新 |

## 7. 与用户上下文的关系

`common.biz.user` 不是分组业务本身，而是分组功能复用的登录基础设施：

```text
UserInfoDTO
定义登录用户信息的 Java 结构
        ↓
UserTransmitFilter
根据 Header 从 Redis 恢复登录用户
        ↓
UserContext
在本次请求期间保存和提供用户信息
        ↓
GroupServiceImpl
获取当前用户名并隔离用户数据
```

`UserInfoDTO` 不是 Redis 数据结构本身，而是 Redis 中用户 JSON 反序列化后对应的 Java 对象模型。

## 8. 当前限制与后续优化

- `saveGroup()` 和 `listGroup()` 没有显式判断用户是否登录，Token 无效时可能得到 `username = null`。
- `UserTransmitFilter` 在登录态校验失败后不会直接拦截请求。
- DTO 尚未添加分组名称非空、长度和 `gid` 格式等参数校验。
- `gid` 采用“先查询、后插入”避免重复，并发下仍应使用数据库唯一索引托底。
- `hasGid()` 返回 `true` 实际表示“不存在、可使用”，方法名容易引起误解。
- 排序逐条执行更新，尚未使用批量 SQL 或事务保证整体一致性。
- `sql` 目录中尚未找到 `t_group` 建表脚本。
- `project` 短链接业务模块尚未发现对 `gid` 的使用，还没有形成“短链接绑定分组”的完整闭环。

## 9. 完成状态

分组的新增、查询、修改、逻辑删除和排序代码均已实现。正常调用时需要先登录，并在每次请求中携带当前账号对应的 `username + token` Header。
