# 用户功能说明

## 1. 功能概述

用户模块位于 `admin` 服务，当前已实现以下功能：

- 根据用户名查询用户信息
- 查询用户原始信息（不进行手机号脱敏）
- 判断用户名是否可注册
- 用户注册
- 修改用户信息
- 用户登录
- 检查登录状态
- 用户退出登录

主要代码位置：

- 控制层：`admin/src/main/java/com/nageoffer/shortlink/admin/controller/UserController.java`
- 服务接口：`admin/src/main/java/com/nageoffer/shortlink/admin/service/UserService.java`
- 服务实现：`admin/src/main/java/com/nageoffer/shortlink/admin/service/impl/UserServiceImpl.java`
- 用户实体：`admin/src/main/java/com/nageoffer/shortlink/admin/dao/entity/UserDO.java`
- 数据库脚本：`sql/create_link_t_user.sql`
- 分表及加密配置：`admin/src/main/resources/shardingsphere-config.yaml`

## 2. 接口清单

服务默认访问地址示例：`http://127.0.0.1:8002`。

| 功能 | 方法 | 路径 | 参数位置 | 返回数据 |
| --- | --- | --- | --- | --- |
| 查询用户 | GET | `/api/shortlink/v1/user/{username}` | Path | `UserRespDTO` |
| 查询原始用户信息 | GET | `/api/shortlink/v1/actual/user/{username}` | Path | `UserActualRespDTO` |
| 判断用户名是否可用 | GET | `/api/shortlink/v1/user/has-username` | Query：`username` | `Boolean` |
| 注册用户 | POST | `/api/shortlink/v1/user` | JSON Body | 无 |
| 修改用户 | PUT | `/api/shortlink/v1/user` | JSON Body | 无 |
| 用户登录 | POST | `/api/shortlink/v1/user/login` | JSON Body | `token` |
| 检查登录状态 | GET | `/api/short-link/v1/user/check-login` | Query：`username`、`token` | `Boolean` |
| 退出登录 | DELETE | `/api/short-link/v1/user/logout` | Query：`username`、`token` | 无 |

注意：前六个接口使用路径前缀 `/api/shortlink`，登录检查和退出接口目前使用 `/api/short-link`，调用时不要混用。

## 3. 请求示例

### 3.1 注册用户

```http
POST /api/shortlink/v1/user
Content-Type: application/json

{
  "username": "aaa",
  "password": "123456",
  "realName": "测试用户",
  "phone": "13800138000",
  "mail": "aaa@example.com"
}
```

注册流程：

1. 使用布隆过滤器快速判断用户名是否可能已存在。
2. 使用 `用户注册锁前缀 + username` 获取 Redisson 分布式锁，避免并发重复注册。
3. 将用户写入 MySQL。
4. 注册成功后把用户名加入布隆过滤器。
5. 如果数据库检测到重复数据，则以数据库结果为准，并补充布隆过滤器数据。

### 3.2 用户登录

```http
POST /api/shortlink/v1/user/login
Content-Type: application/json

{
  "username": "aaa",
  "password": "123456"
}
```

成功响应的核心数据：

```json
{
  "code": "0",
  "data": {
    "token": "生成的 UUID"
  }
}
```

登录成功后，服务将登录态保存到 Redis Hash：

```text
Redis Key: login_{username}
Hash Field: token
Hash Value: 用户信息 JSON
有效期: 30 分钟
```

同一用户名存在未过期登录态时，当前实现不允许重复登录。

### 3.3 检查登录状态

```http
GET /api/short-link/v1/user/check-login?username=aaa&token={登录返回的token}
```

服务通过检查 Redis Hash `login_aaa` 中是否存在对应 token，返回 `true` 或 `false`。

### 3.4 退出登录

```http
DELETE /api/short-link/v1/user/logout?username=aaa&token={登录返回的token}
```

退出流程：

1. 校验 `login_{username}` 中是否存在传入的 token。
2. 校验成功后删除整个 `login_{username}` Redis Key。
3. token 不存在或登录态已过期时，返回“用户 token 不存在或用户未登录”。

退出功能曾因重复拼接 Redis Key 前缀而错误查询 `login_login_{username}`，现已修复为只拼接一次前缀。

## 4. 用户数据

用户实体对应逻辑表 `t_user`，主要字段如下：

| 字段 | 含义 |
| --- | --- |
| `id` | 自增主键 |
| `username` | 用户名 |
| `password` | 密码 |
| `real_name` | 真实姓名 |
| `phone` | 手机号 |
| `mail` | 邮箱 |
| `deletion_time` | 注销时间戳 |
| `create_time` | 创建时间 |
| `update_time` | 修改时间 |
| `del_flag` | 删除标识：0 未删除，1 已删除 |

ShardingSphere 根据 `username` 的 Hash 将用户数据分散到 16 张表：

```text
t_user_0 ～ t_user_15
```

手机号和邮箱通过 ShardingSphere AES 规则加密存储。普通用户查询返回的手机号还会经过 `PhoneDesensitizationSerializer` 脱敏；原始用户查询接口不进行该响应脱敏。

## 5. 布隆过滤器

Redis 布隆过滤器名称为：

```text
userRegisterCachePenetrationBloomFilter
```

预期容量为 1 亿条数据，误判率为 `0.001`。应用启动时会读取数据库中的历史用户名并同步到布隆过滤器，以免已有用户名被当作可注册用户名。

`has-username` 接口当前返回的是“用户名是否可用”：

- `true`：布隆过滤器判断用户名不存在，可以尝试注册。
- `false`：用户名可能已经存在，不允许注册。

## 6. 统一响应

接口使用统一响应对象 `Result<T>`，主要字段如下：

```json
{
  "code": "0",
  "message": null,
  "data": null,
  "requestId": null
}
```

其中 `code = "0"` 表示业务处理成功。业务失败时会返回对应错误码与错误信息；HTTP 状态码可能仍为 200，因此调用方应同时判断响应体中的 `code` 或 `success` 展示字段。

## 7. 当前限制与后续优化

目前用户主流程已经可用，但仍建议继续完善以下内容：

- 密码当前直接参与数据库查询，尚未使用 BCrypt、Argon2 等单向哈希算法存储和校验。
- DTO 尚未添加用户名、密码、手机号和邮箱等字段的参数校验注解。
- 修改用户接口中的登录用户身份校验仍是 TODO。
- 登录检查和退出接口的 `/api/short-link` 前缀与其他用户接口不统一。
- 注册数据库脚本中应为 `username` 建立唯一索引，才能可靠兜底并发重复注册。
- 分布式锁释放前应确认当前线程确实持有锁，避免未获取锁时调用 `unlock()`。
- 原始用户信息接口会返回未脱敏手机号和邮箱，应增加身份认证与权限控制。
- 当前登录态按用户名整体删除，只支持单端登录模型；如需多端登录，应在退出时仅删除对应 token 字段。

## 8. 完成状态

用户查询、用户名检查、注册、修改、登录、登录态检查及退出登录流程均已实现。退出登录的 Redis Key 重复前缀问题已经修复，重启 `admin` 服务后即可使用最新代码测试完整流程。
