# 用户模块代码结构解析

## 1. 整体结构

用户模块位于 `admin` 服务中，核心代码结构如下：

```text
admin
├─ pom.xml
└─ src
   └─ main
      ├─ java/com/nageoffer/shortlink/admin
      │  ├─ ShortLinkAdminApplication.java
      │  ├─ common
      │  ├─ config
      │  ├─ controller
      │  ├─ dao
      │  │  ├─ entity
      │  │  └─ mapper
      │  ├─ dto
      │  │  ├─ req
      │  │  └─ resp
      │  └─ service
      │     └─ impl
      └─ resources
         ├─ application.yaml
         └─ shardingsphere-config.yaml
```

各层的核心职责可以简单记为：

```text
启动类      启动并组装整个 Spring Boot 应用
Controller 接收 HTTP 请求并返回响应
DTO        定义接口传输的数据
Service    组织和执行具体业务流程
DAO        访问数据库
Config     配置框架能力和需要交给 Spring 管理的对象
Common     提供各业务都会使用的公共能力和规范
Resources  保存项目运行配置和其他非 Java 资源
pom.xml    描述 Maven 项目、依赖、模块和构建规则
```

## 2. 一次请求的完整链路

以用户登录为例：

```text
Apifox / 前端
    ↓ 发送 JSON 请求
Controller
    ↓ 将 JSON 转成 UserLoginReqDTO
Service
    ↓ 组织登录业务
Mapper
    ↓ 生成并执行 SQL
MySQL
    ↓ 返回数据库记录
UserDO
    ↓ Service 校验并生成 Token
UserLoginRespDTO
    ↓ Results.success(...) 包装
Result<UserLoginRespDTO>
    ↓ 转换成 JSON
Apifox / 前端
```

对应的分层原则是：

- Controller 负责接收和返回，不堆积业务逻辑。
- Service 负责业务规则和流程编排。
- Mapper 负责数据库增删改查。
- DO 承接数据库数据。
- ReqDTO 和 RespDTO 隔离接口数据与数据库数据。
- Common 统一处理响应、异常、错误码等重复能力。

## 3. Spring Boot 启动类

`ShortLinkAdminApplication` 是 `admin` 服务的程序入口，相当于 Spring Boot 版本的 `main`：

```java
@SpringBootApplication
public class ShortLinkAdminApplication {

    public static void main(String[] args) {
        SpringApplication.run(ShortLinkAdminApplication.class, args);
    }
}
```

执行后，Spring Boot 会完成：

- 创建 Spring 容器。
- 扫描并创建 Controller、Service、Component、Configuration 等对象。
- 执行自动配置。
- 加载 `resources` 中的配置。
- 创建数据库、Redis 等相关组件。
- 启动内嵌 Web 服务器。
- 注册 Controller 中定义的 HTTP 接口。

## 4. Controller：接口入口层

Controller 是正式接收 HTTP 请求的地方，不是测试接口的地方。Apifox、Postman 或前端才是请求接口的一方。

例如：

```java
@PostMapping("/api/shortlink/v1/user/login")
public Result<UserLoginRespDTO> login(
        @RequestBody UserLoginReqDTO requestParam) {
    return Results.success(userService.login(requestParam));
}
```

这段代码完成：

1. 使用 `@PostMapping` 定义请求方法和路径。
2. 使用 `@RequestBody` 将请求 JSON 转成 Java 对象。
3. 调用 Service 处理登录业务。
4. 使用 `Results.success()` 包装统一响应。

Controller 通常不应该直接承担：

- 查询或修改数据库。
- 操作 Redis。
- 获取分布式锁。
- 判断复杂业务规则。
- 编写大量 `try-catch`。

这些职责应分别交给 Service、DAO 和全局异常处理器。

常见参数注解：

```java
@RequestBody       // 接收 JSON 请求体
@RequestParam      // 接收 URL 查询参数，例如 ?username=aaa
@PathVariable     // 接收路径变量，例如 /user/aaa
```

## 5. DTO：接口数据传输对象

DTO 全称为 `Data Transfer Object`，即数据传输对象。DTO 与具体业务场景密切相关。

### 5.1 ReqDTO

`req` 是 Request 的缩写，表示前端传给后端的数据，也就是在 Apifox 中输入的请求参数。

登录只需要用户名和密码：

```java
public class UserLoginReqDTO {
    private String username;
    private String password;
}
```

对应请求：

```json
{
  "username": "aaa",
  "password": "123456"
}
```

注册业务需要的信息更多，因此使用独立的 `UserRegisterReqDTO`。不同业务使用不同 DTO，可以让字段含义和参数校验更清楚。

### 5.2 RespDTO

`resp` 是 Response 的缩写，表示后端返回给前端的业务数据，通常对应 `Result<T>` 中的 `data`。

登录成功只需要返回 Token：

```java
public class UserLoginRespDTO {
    private String token;
}
```

统一响应大致为：

```json
{
  "code": "0",
  "message": null,
  "data": {
    "token": "xxxx-xxxx"
  },
  "requestId": null
}
```

### 5.3 DTO 与 DO 的区别

```text
ReqDTO  前端需要传给后端什么
RespDTO 后端允许返回给前端什么
DO      数据库中的数据在 Java 中是什么样
```

DO 可能包含密码、删除标识、创建时间等完整数据库字段，不应直接返回给前端。使用 RespDTO 可以隐藏密码等敏感字段，同时避免接口结构与数据库结构强耦合。

## 6. Service：业务逻辑层

Service 包目前由接口和实现类组成：

```text
service
├─ UserService.java
└─ impl
   └─ UserServiceImpl.java
```

### 6.1 Service 接口

接口定义“用户模块能做什么”：

```java
public interface UserService {
    UserRespDTO getUserByUsername(String username);
    void Register(UserRegisterReqDTO requestParam);
    UserLoginRespDTO login(UserLoginReqDTO requestParam);
    Boolean checkLogin(String username, String token);
    void logout(String username, String token);
}
```

接口只声明能力，不描述具体实现过程。

### 6.2 ServiceImpl 实现类

实现类定义“这些业务具体怎么做”：

```java
@Service
public class UserServiceImpl implements UserService {
    // 实现注册、登录、查询和退出等业务
}
```

Service 是业务编排层，会综合使用：

- ReqDTO：接收业务参数。
- RespDTO：返回业务结果。
- UserDO：承接数据库数据。
- BaseMapper/UserMapper：访问数据库。
- RedisTemplate：保存登录状态。
- RedissonClient：使用分布式锁。
- RBloomFilter：判断用户名是否可能存在。
- 自定义异常和错误码：表达业务失败。

以注册为例：

```text
检查布隆过滤器
    ↓
获取用户名对应的分布式锁
    ↓
使用 Mapper 写入数据库
    ↓
把用户名加入布隆过滤器
    ↓
发生业务错误时抛出统一异常
```

因此 Service 不只是调用 `BaseMapper`，而是将数据库、Redis、锁、异常等基础能力按照业务规则组织起来。

Controller 依赖 `UserService` 接口，而不是直接依赖 `UserServiceImpl`，这样可以降低 Controller 与具体实现之间的耦合。

## 7. DAO：数据访问层

DAO 全称为 `Data Access Object`，负责访问数据库。

```text
dao
├─ entity
│  └─ UserDO.java
└─ mapper
   └─ UserMapper.java
```

### 7.1 Entity/DO

`UserDO` 描述数据库用户数据在 Java 中是什么样：

```java
@TableName("t_user")
public class UserDO {
    private Long id;
    private String username;
    private String password;
    private String realName;
    private String phone;
    private String mail;
    private LocalDateTime createTime;
    private LocalDateTime updateTime;
    private Integer delFlag;
}
```

常见对应关系：

```text
Java 字段  realName
数据库字段 real_name
```

DO 可以理解为数据库一行记录在 Java 中的表示。

### 7.2 Mapper

Mapper 提供数据库增删改查能力：

```java
public interface UserMapper extends BaseMapper<UserDO> {
}
```

继承 MyBatis-Plus 的 `BaseMapper<UserDO>` 后，会自动获得：

```java
insert(...)
deleteById(...)
updateById(...)
selectById(...)
selectOne(...)
selectList(...)
```

例如：

```java
userMapper.insert(userDO);
```

MyBatis-Plus 会生成类似的 SQL 并交给数据库执行：

```sql
INSERT INTO t_user (...) VALUES (...);
```

Mapper 的完整作用是：

```text
接收 Java 方法调用
    ↓
MyBatis-Plus 生成 SQL
    ↓
数据库执行 SQL
    ↓
将查询结果转换成 UserDO
    ↓
返回给 Service
```

## 8. Common：公共能力和项目规范

`common` 不直接完成某个具体业务，而是提供多个业务都会使用的公共基础能力。

```text
common
├─ constant
├─ convention
│  ├─ errorcode
│  ├─ exception
│  └─ result
├─ enums
├─ serialize
└─ web
```

### 8.1 constant

保存公共常量，例如 Redis Key 前缀：

```java
public static final String LOCK_USER_REGISTER_KEY =
        "short-link:lock_user-register:";
```

这样可以避免在各处重复手写字符串，修改命名时也只需要改一个地方。

### 8.2 errorcode

`IErrorCode` 规定所有错误码都要提供：

```java
String code();
String message();
```

`BaseErrorCode` 定义项目级基础错误码，例如：

```text
A 类 用户或客户端问题
B 类 服务内部执行问题
C 类 调用第三方服务的问题
```

### 8.3 exception

项目异常体系为：

```text
AbstractException
├─ ClientException   客户端或业务操作问题
├─ ServiceException  本服务内部执行问题
└─ RemoteException   调用外部服务的问题
```

业务代码发现错误后可以直接抛出：

```java
throw new ClientException(USER_NAME_EXIST);
```

不需要在每一层重复返回错误结果。

### 8.4 Result 与 Results

`Result<T>` 规定接口响应包含哪些字段：

```java
public class Result<T> {
    private String code;
    private String message;
    private T data;
    private String requestId;
}
```

其中 `T` 是类型占位符，在当前类中代表 `data` 的具体类型：

```text
Result<UserRespDTO>      → data 是 UserRespDTO
Result<Boolean>          → data 是 Boolean
Result<UserLoginRespDTO> → data 是 UserLoginRespDTO
Result<Void>             → 没有实际 data
```

`Results` 是创建并填充 `Result<T>` 的工具类：

```java
Results.success(data);
Results.failure(errorCode, errorMessage);
Results.failure(exception);
```

可以简单记为：

```text
Result  规定返回对象长什么样
Results 按成功或失败场景实际填写 Result
```

### 8.5 enums

当前保存用户业务相关的具体错误码，例如：

```text
USER_NULL
USER_NAME_EXIST
USER_EXIST
USER_SAVE_ERROR
```

这些枚举实现 `IErrorCode` 后，可以直接交给自定义异常使用。

### 8.6 serialize

`PhoneDesensitizationSerializer` 负责手机号响应脱敏：

```text
13800138000 → 138****8000
```

这是脱敏，不是加密：

- 脱敏用于隐藏展示内容，通常不能从脱敏结果恢复原值。
- 加密可以通过正确密钥解密得到原值。

项目中 ShardingSphere 对手机号和邮箱的 AES 处理才属于数据库加密。

### 8.7 web

`GlobalExceptionHandler` 是全局异常处理器，它会统一拦截：

- 参数校验异常。
- 项目自定义异常。
- 其他未捕获异常。

处理流程：

```text
Service 抛出异常
    ↓
GlobalExceptionHandler 捕获
    ↓
记录日志
    ↓
Results.failure(...) 创建统一错误响应
    ↓
返回前端
```

因此业务代码通常不需要在每个 Controller 中重复编写 `try-catch`。这是一种常见的项目规范，但具体写法可以根据项目需求扩展，并非完全固定。

## 9. Config：框架配置层

`config` 包用于告诉 Spring 和其他框架：项目启动时要准备哪些对象，以及框架功能应如何运行。

当前包含：

```text
config
├─ MyMetaObjectHandler.java
└─ RBloomFilterConfiguration.java
```

### 9.1 MyMetaObjectHandler

这是 MyBatis-Plus 的字段自动填充器，定义数据库公共字段的填充规则：

```text
新增时：createTime = 当前时间
新增时：updateTime = 当前时间
新增时：delFlag = 0
更新时：updateTime = 当前时间
```

实体字段上的 `@TableField` 决定什么时候填充：

```java
@TableField(fill = FieldFill.INSERT)
private LocalDateTime createTime;

@TableField(fill = FieldFill.INSERT_UPDATE)
private LocalDateTime updateTime;
```

`MyMetaObjectHandler` 决定具体填充什么值。

### 9.2 RBloomFilterConfiguration

这个配置类负责：

1. 通过 Redisson 获取并初始化注册用的布隆过滤器。
2. 把 `RBloomFilter<String>` 注册到 Spring 容器。
3. 在应用启动后查询历史用户名并同步到布隆过滤器。

布隆过滤器实际数据保存在 Redis 中，Spring 容器里的 `RBloomFilter<String>` 对象是操作它的入口。

## 10. Spring Bean 与依赖注入

### 10.1 Bean 是什么

Bean 可以先理解成：

> 由 Spring 创建、保存和管理的 Java 对象。

Spring 容器中可能保存：

```text
UserController
UserServiceImpl
UserMapper
MyMetaObjectHandler
StringRedisTemplate
RedissonClient
RBloomFilter
```

### 10.2 `@Component` 与 `@Bean`

两者最终目的相同：把对象交给 Spring 管理。区别是对象如何产生。

```java
@Component
public class MyMetaObjectHandler {
}
```

表示 Spring 直接创建并管理当前类。

```java
@Configuration
public class RBloomFilterConfiguration {

    @Bean
    public RBloomFilter<String> bloomFilter(
            RedissonClient redissonClient) {
        return redissonClient.getBloomFilter("userBloomFilter");
    }
}
```

表示 Spring 执行这个方法，并管理方法返回的对象。

常用判断方式：

- 自己编写且创建简单的类，常用 `@Component`、`@Service`、`@Controller`。
- 第三方类或需要特殊初始化过程的对象，常用 `@Configuration + @Bean`。
- `@Bean` 也能注册自己写的类，并不是只能用于第三方对象。

### 10.3 依赖注入

依赖注入的含义是：

> 对象的创建和组装交给 Spring；一个类需要其他对象时，只声明依赖，由 Spring 把实际对象传进来。

例如：

```java
@RestController
@RequiredArgsConstructor
public class UserController {
    private final UserService userService;
}
```

`private final UserService userService` 只是声明一个引用，并没有执行 `new`。Spring 会找到 `UserServiceImpl` 对象，通过构造方法传给 Controller。

可以近似理解为：

```java
UserService service = Spring容器取出UserService对象();
UserController controller = new UserController(service);
```

依赖注入的主要价值：

- 减少手动 `new` 和复杂的对象组装代码。
- 统一管理对象的创建、初始化和销毁。
- 让代码依赖接口而不是具体实现。
- 更容易替换实现和进行单元测试。

## 11. Resources：运行资源

`src/main/resources` 主要存放非 Java 资源。

当前项目包括：

- `application.yaml`：服务端口、Redis、Spring 等基础配置。
- `shardingsphere-config.yaml`：数据源、用户分表和字段加密规则。

`resources` 也可以存放：

- MyBatis XML。
- 日志配置。
- 国际化文件。
- 静态资源。
- 模板文件。

## 12. pom.xml：Maven 项目说明

`pom.xml` 不只是依赖列表，它描述整个 Maven 项目的构建信息，包括：

- 项目名称、坐标和版本。
- 父子模块关系。
- Java 版本。
- 第三方依赖。
- Maven 插件。
- 编译、测试和打包规则。

例如引入 Redis 依赖后，项目才能使用相关类和 Spring Boot 自动配置：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-redis</artifactId>
</dependency>
```

## 13. 常见注解速查

| 注解 | 作用 |
| --- | --- |
| `@SpringBootApplication` | 标记 Spring Boot 启动类 |
| `@RestController` | 把类注册为接收 HTTP 请求的 Controller |
| `@Service` | 把类注册为业务层 Bean |
| `@Component` | 把当前类注册为 Spring Bean |
| `@Configuration` | 标记 Spring 配置类 |
| `@Bean` | 把方法返回的对象注册为 Spring Bean |
| `@RequiredArgsConstructor` | Lombok 为 `final` 字段生成构造方法，便于构造器注入 |
| `@Data` | Lombok 生成 Getter、Setter、`toString` 等方法 |
| `@Accessors(chain = true)` | 让 Setter 支持链式调用 |
| `@PostMapping` 等 | 定义 HTTP 方法和接口路径 |
| `@RequestBody` | 将请求 JSON 转成 Java 对象 |
| `@RequestParam` | 接收查询参数 |
| `@PathVariable` | 接收 URL 路径变量 |
| `@TableName` | 指定 DO 对应的数据库表 |
| `@TableField` | 配置数据库字段映射或自动填充规则 |
| `@JsonSerialize` | 指定字段转换成 JSON 时使用的序列化器 |
| `@RestControllerAdvice` | 声明全局 Controller 增强类 |
| `@ExceptionHandler` | 指定方法处理哪种异常 |

## 14. 分层记忆总结

```text
Apifox / 前端：发送请求和查看响应
Controller：接收请求
ReqDTO：承接请求参数
Service：处理和组织业务
Mapper：操作数据库
DO：承接数据库记录
RespDTO：承接需要返回的业务数据
Result：规定统一响应结构
Results：创建并填充统一响应
GlobalExceptionHandler：统一处理异常
Config：配置和准备框架组件
Common：提供公共能力和统一规范
Spring：创建、管理并组装这些对象
```

最简请求链路：

```text
请求 → Controller → Service → Mapper → 数据库
响应 ← Result 包装 ← RespDTO ← Service ← 查询结果
```
